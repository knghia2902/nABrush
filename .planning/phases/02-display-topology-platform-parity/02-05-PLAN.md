<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Checked-in JSON fixture → TypeScript/Rust loaders | Repository data controls shortcut, tool, mode-feedback, and export semantic values used by both target paths. |
| Webview/E2E invoke → native parity command | A caller can request the parity payload but must not replace or mutate the checked-in contract. |
| Parity contract → later renderer/capture consumers | Declarative inclusion and exclusion flags influence user-visible mode/export behavior. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-19 | Tampering | TypeScript/Rust parity fixture | high | mitigate | Validate the same checked-in schema in Vitest and Rust, preserve exact ordered arrays, and compare native serialization with the fixture in both target E2E jobs. |
| T-02-20 | Tampering | `platform_parity_contract` command | medium | mitigate | Return only the embedded validated fixture, accept no replacement values, and keep the command read-only with no scene, viewport, shortcut, or permission mutations. |
| T-02-21 | Denial of service | parity schema parsing | medium | mitigate | Reject malformed or oversized semantic arrays during native validation and fail the command with a typed error before it reaches renderer or E2E state. |
| T-02-SC | Tampering | npm/cargo installs | high | mitigate | No package installation is planned; retain the phase package-legitimacy gate if an executor proposes a dependency change. |
