<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Renderer command/event bridge → Rust registry | Webview input can request scene commits or retries and receives viewport/state events. |
| Rust registry → native Tauri windows | Validated monitor descriptors become window labels, geometry, visibility, and hit-testing calls. |
| Native compositor/display callback → app runtime | OS notifications trigger reconciliation work that can create or destroy windows. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-05 | Elevation of privilege | dynamic label/window creation | high | mitigate | Generate labels and target windows solely from validated Rust `DisplayId` values; do not accept arbitrary renderer labels or URLs. |
| T-02-06 | Denial of service | WebView2/AppKit creation path | high | mitigate | Schedule `WebviewWindowBuilder` work asynchronously outside synchronous display callbacks, coalesce bursts, and update unchanged windows in place. |
| T-02-07 | Tampering | global mode/click-through transaction | high | mitigate | Registry iterates every viewport, applies native hit-testing, and emits shared mode state only after all operations have been validated. |
| T-02-08 | Tampering | SceneStore command boundary | high | mitigate | Validate scene IDs and finite coordinate payloads in Rust, keep the scene store managed state, and broadcast only accepted items. |
| T-02-09 | Denial of service | compositor/native failure | high | mitigate | Preserve controller and SceneStore state, hide or mark only the failed viewport, and publish a typed retry/settings action through `ErrorStore`. |
</threat_model>
