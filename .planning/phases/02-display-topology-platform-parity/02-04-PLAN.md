## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| OS display/compositor events → target adapter | Native messages and screen notifications trigger refresh and capability decisions. |
| WebDriver/debug fixture → built Tauri process | Test-only commands exercise registry state and recovery paths. |
| Device observations → support documentation | Hardware results become user-facing support claims. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-14 | Denial of service | native topology callbacks | high | mitigate | Return promptly from callbacks, coalesce refreshes, and schedule window work asynchronously through the registry. |
| T-02-15 | Tampering | full-screen support claims | high | mitigate | Require target-specific manual evidence, separate Supported/Limited/Unsupported rows, and never infer exclusive support from topmost behavior. |
| T-02-16 | Denial of service | blocked/protected/compositor surface | high | mitigate | Preserve registry/scene state, publish a typed scoped error, keep healthy viewports usable, and provide retry/settings actions. |
| T-02-17 | Tampering | E2E debug fixtures | medium | mitigate | Keep fixtures debug-only, validate their descriptor payloads in Rust, and keep release commands fail-closed. |
| T-02-18 | Information disclosure | support matrix | low | accept | Record OS/display capability outcomes and evidence references without screen pixels, user content, or credentials. |
</threat_model>
