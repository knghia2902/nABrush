## Spec-less edge probe coverage

The Phase 4 spec-less fallback produced 12 unresolved probes. Each is listed
individually below with a conservative interpretation and an executable plan
location so no probe is silently dropped.

1. `EDIT-01 / adjacency`: touching/equal scene items are separate operations; erase and history never merge them — Task 04-02-03 tests.
2. `EDIT-01 / empty`: Undo/Redo on an empty history and clear-all on an empty scene are no-ops with no broadcast — Task 04-02-01 tests.
3. `EDIT-01 / encoding`: history stores exact Unicode text and does not split surrogate pairs/graphemes — Task 04-02-02 tests.
4. `EDIT-01 / ordering`: equal snapshot timestamps retain stable scene-vector order — Task 04-02-03 tests.
5. `EDIT-02 / adjacency`: clear-all treats every item as a member and does not merge touching/equal geometry — Task 04-02-01 acceptance and Task 04-02-03 tests.
6. `EDIT-02 / empty`: clear-all on an empty scene is a no-op and cannot create an Undo entry — Task 04-02-01 tests.
7. `EDIT-02 / ordering`: clear-all Undo restores the exact prior item order — Task 04-02-01 acceptance.
8. `EDIT-03 / unclassified`: switching lifecycle affects only future items and history restore does not rewrite the active lifecycle control — Task 04-02-03 tests.
9. `EDIT-04 / unclassified`: an expired Vanishing item creates no extra history entry and its creation can be restored by Undo — Task 04-02-03 tests.
10. `EDIT-05 / unclassified`: toolbar lifecycle state remains visible, scene-excluded, and independent of restored scene contents — Task 04-02-03 tests.
11. `EDIT-06 / empty`: an unconfigured/new tool uses its existing default style and empty style history does not mutate other tools — Task 04-02-03 tests.
12. `EDIT-06 / encoding`: text-size/style memory is keyed by tool, not by text encoding or string length — Task 04-02-02 and Task 04-02-03 tests.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| React/webview → native history command | Keyboard, toolbar, and pointer events produce JSON scene mutations at the Tauri command boundary. |
| Native history store → scene-changed event | Restored snapshots are broadcast to all display overlays and can affect visibility immediately. |
| Text editor → retained scene | User-provided Unicode text and coordinates enter the canonical scene only at commit/move boundaries. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-02 | Tampering | undo/redo/clear commands | high | mitigate | Validate stack direction, snapshot shape, IDs, geometry, lifecycle metadata, and item count under one mutex; reject malformed requests without mutating the prior scene. |
| T-04-03 | Denial of service | history stacks and text input | medium | mitigate | Bound history depth and text/geometry payloads, coalesce no-op moves, keep drafts out of the retained scene, and avoid unbounded per-key event writes. |
| T-04-04 | Elevation of privilege | toolbar shortcuts and click-through mode | medium | mitigate | Keep toolbar/editor scene-excluded, scope keyboard handling to the overlay/editor, and preserve native click-through authority. |
| T-04-05 | Information disclosure | test logs and history snapshots | low | accept | Keep history in process memory only; do not log screen pixels or full user text, and do not add persistence/network transport in this phase. |
</threat_model>
