Current contracts to extend without creating display-local state:

- `SceneItem` is the TypeScript discriminated union for stroke, shape, and text items; `SceneSnapshot` is `{ sceneId, items }` and native `SceneStore::snapshot()` is the canonical source.
- `createStroke`, `transientSceneItemForGesture`, `transientGeometryForGesture`, `drawScene`, and the `OverlaySurface` `onCommitSceneItem` callback are the existing gesture/render seams.
- `createInitialAnnotationState`, `updateToolStyle`, and `stylesByTool` are the only per-tool style memory path.
- `AnnotationToolbar` is controlled by `activeTool`, `toolStyle`, `propertyOpen`, and callback props; its root and popover already carry `data-scene-excluded="true"`.
- Native `commit_scene_item`, `erase_scene_item`, and `move_text_scene_item` lock `Mutex<SceneStore>`, return a complete `SceneSnapshot`, broadcast through `OverlayRegistry`, and are registered in `tauri::generate_handler!`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| React/webview → Tauri scene command | Renderer-controlled JSON crosses into the native canonical scene store. |
| Native scheduler → shared overlay event | A background native worker changes scene visibility and broadcasts to every display webview. |
| Pointer/keyboard input → React gesture state | Untrusted physical or WebDriver input can attempt to create malformed or duplicate annotations. |
| In-memory scene → future local export | Lifecycle metadata will later be consumed by local capture/export code; this phase does not persist or upload it. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Tampering | `commit_scene_item` and lifecycle JSON normalization | high | mitigate | Validate lifecycle mode, finite positive duration, timestamp, typed item shape, IDs, styles, and geometry before mutation; return the prior scene unchanged on rejection. |
| T-04-02 | Denial of service | Expiry scheduler and animation redraw | medium | mitigate | Bound duration and item metadata, poll one canonical store, remove due items in a bounded pass, clean animation-frame/observer registrations, and never schedule from unbounded input. |
| T-04-03 | Elevation of privilege | Toolbar, duration popover, and text editor | medium | mitigate | Keep controls scene-excluded, route mutations through typed callbacks/native validation, and retain native hit-testing/click-through authority. |
| T-04-04 | Information disclosure | Scene/history memory and diagnostics | low | accept | Phase 4 keeps scene and lifecycle metadata in process memory, adds no persistence or network transport, and test diagnostics must avoid logging full text or screen content. |
</threat_model>
