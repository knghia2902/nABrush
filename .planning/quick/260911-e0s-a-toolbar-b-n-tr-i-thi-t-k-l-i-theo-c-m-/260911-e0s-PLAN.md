## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Desktop/webview pointer and keyboard events → toolbar position state | Untrusted event coordinates and key input control UI placement. |
| Toolbar chrome → retained Canvas scene | Toolbar interactions share the transparent overlay surface but must not reach `OverlaySurface` gesture handlers or scene mutation callbacks. |
| React mode state → visible toolbar DOM | `VisibleInteractive` is the trusted visibility contract for interactive controls; click-through must remain pass-through. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-260911-01 | Tampering | `AnnotationToolbar` position state | medium | mitigate | Validate finite candidate coordinates, preserve the active pointer identity, clamp against measured viewport/toolbar bounds, and re-clamp on resize before applying CSS coordinates. |
| T-260911-02 | Denial of service | toolbar drag lifecycle | medium | mitigate | Use pointer capture with explicit up/cancel/lost-capture/blur cleanup so a canceled or interrupted drag cannot leave the toolbar locked or consume later drawing input. |
| T-260911-03 | Tampering | toolbar-to-canvas event boundary | high | mitigate | Keep the toolbar and handle scene-excluded with opt-in pointer events, never invoke scene callbacks from the drag path, and assert unchanged scene IDs plus an idle canvas gesture marker in the native suite. |
| T-260911-04 | Spoofing | tool selection and property controls | low | mitigate | Preserve stable accessible names, `aria-pressed`, `aria-expanded`, `aria-controls`, focus-visible styling, and existing data selectors while changing only the presentation hierarchy. |
